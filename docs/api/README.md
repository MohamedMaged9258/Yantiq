# API documentation

## Authoritative sources

Per [`../phase-0-baseline.md`](../phase-0-baseline.md) §5.3, the **OpenAPI document
generated by FastAPI is the authoritative specification** for the mobile and admin
clients. Do not hand-maintain a parallel spec here — this directory holds conventions,
exported snapshots, and the notes that OpenAPI cannot express.

- Client-facing surface: `contracts/application-api/`
- Backend↔AI surface: `contracts/ai-api/`
- Cross-service semantics: `contracts/shared/integration-rules.md`

[`operation-map.md`](operation-map.md) is a readable index of both contracts — one row per
operation, with the authorization and ownership rule each one enforces. It describes the
**proposed** surface; the field definitions stay authoritative in the OpenAPI files, and
where those conflict with the baseline, the baseline wins.

## Conventions (baseline §10)

- REST under `/api/v1`.
- `GET /health/live` and `GET /health/ready` on every deployed service, outside `/api/v1`.
- A consistent error envelope on every endpoint.
- A correlation ID on every request, propagated into structured logs.
- Pydantic-validated request and response schemas.
- Server-side authorization on every protected endpoint — guardian ownership for child
  resources, administrator role for the `/api/v1/admin/...` group.

## Logging and privacy constraints (§13)

Structured JSON logs carry request IDs and internal UUIDs only. **No child data and no
audio may appear in logs.** Raw child audio is deleted after scoring or after failure.

## Rate limiting

Authentication-sensitive endpoints and the evaluation endpoint are rate limited. Uploads
are checked for both declared type and size before any processing.
