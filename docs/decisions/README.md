# Architecture decision records

An ADR records a decision that is **not derivable from the code** — the alternatives that
were considered and why one was chosen. Decisions already settled by
[`../phase-0-baseline.md`](../phase-0-baseline.md) do not need backfilled ADRs; cite the
baseline section instead. Write an ADR when a decision is made *after* Phase 0, or when
Phase 0 is being amended.

## Template

```markdown
# ADR-000N: <short title in the imperative>

- **Status:** Proposed | Accepted | Superseded by ADR-000M
- **Date:** YYYY-MM-DD
- **Deciders:** <roles>

## Context

What forced a decision. Constraints, deadlines, and what was already true.

## Decision

What was chosen, stated plainly.

## Alternatives considered

What else was on the table and the specific reason each was rejected.

## Consequences

What becomes easier, what becomes harder, and what has to be revisited later.
```

Number files sequentially: `0001-short-title.md`.
